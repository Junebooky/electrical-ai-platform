## 1. 제품 비전과 정의

한국형 전기공사 AI 통합 플랫폼은 전기공사업체, 설계자, 적산·공무 담당자, 전문 시공·검사·유지보수 인력의 업무를 돕는 전문가용 소프트웨어다. AI는 실제 시공·계측·정비 또는 책임 기술자의 최종 판단을 대신하지 않는다.

**MVP 1**은 DXF뿐 아니라 **PDF(벡터·스캔)와 PNG/JPG 이미지 형태의 2D 전기설계도**를 하나의 웹 뷰어에서 열고, 파일 형식에 따라 가능한 정보를 추출하며, 사용자 검수 후 기구 물량산출표를 CSV/XLSX로 출력하는 **다중 형식 반자동 2D 도면 분석·물량산출 시스템**이다. DWG 원본 직접 업로드는 제외한다. 완전자동 적산·공사비 계산기는 아니다.

**'도면 표시'와 '도면 해석'은 분리한다.** DXF는 CAD 구조를 추출하고, 벡터 PDF는 추출 가능한 문자·선의 위치 정보를 활용하며, 스캔 PDF·이미지는 초기에는 도면상 수동 기호 표시와 검수를 제공한다. PDF/이미지에서 AI가 기호·회로·물량을 자동 확정하는 기능은 후속 단계로 둔다. PDF 도면의 문자를 추출하더라도 도면의 전기적 의미를 정확하게 이해했다는 뜻은 아니다.

**입력 형식의 범용성 ≠ 전 공종 자동 해석.** 첫 MVP의 해석 대상은 전등·전열 등 전기설비 2D 도면이다. 건축·기계·토목 도면 전체의 전문 적산은 포함하지 않는다.

차별화 가설: 원본 CAD 객체, 품목 매핑, 검수 이력, 수량산출표를 추적 가능하게 연결하고 후속 버전에서 설계변경·시방서·현장기록을 통합한다. 경쟁우위는 아직 실증이 필요한 가설이다.

## 2. 타깃 사용자와 문제

- 최초 개발/운영: 한 명의 로컬 사용자. 초기에는 로그인과 다중 사용자 기능을 구축하지 않는다.
- 향후 고객: 국내 전기공사업체 적산·견적·공무 담당자, 전기설계 전문가. 현장 전기기술자와 유지보수 전문가는 후속 모듈 주요 사용자다.
- 문제: 업체·프로젝트별 상이한 CAD 블록/범례, PDF·스캔·사진만 보유한 현장의 접근성 부족, 집계 근거 불투명, 누락과 중복, 수작업 수정 및 기존 산출 양식으로의 재입력.
- 해결: **매핑 → 자동 집계 → 도면상 검수 → 저장 → 근거를 갖춘 수량표 출력**.

## 3. 사용자 흐름

1. 로컬 프로젝트 생성 및 DXF/PDF/PNG/JPG 업로드.
2. 형식 판별(DXF / 텍스트·벡터 추출 가능 PDF / 이미지형 PDF / 래스터 이미지), 페이지 선택 및 2D 뷰어 렌더링.
3. DXF의 블록·레이어·좌표, 벡터 PDF의 추출 가능한 문자/도형 위치를 표시. 스캔·이미지는 추출 한계를 명확하게 안내.
4. DXF에서 미분류 블록을 품목에 매핑. PDF/이미지에서는 사용자가 도면의 기호 위치를 찍어 품목/수량을 수동 등록하고 근거를 남긴다.
5. 매핑한 CAD 대상의 자동 집계, 모든 형식의 수동 표시 위치와 산출표 양방향 연결.
6. 오탐 제외·복원, 품목 수정, 누락 수동 추가, 검수 상태 관리.
7. 산출 수량/근거/경고 확인 후 CSV·XLSX 내보내기, 프로젝트 재열기 시 복구.

A03는 PC 우선 도면 뷰어와 검수 패널의 구체적인 UX·UI 명세를 담당한다.

### P1 (후속)

매핑 템플릿 재사용, 수동 경로 측정과 검증 가능한 길이 산출, 단순 REV 비교, AI 매핑 제안, **벡터 PDF의 반복 기호 패턴 검출, 스캔 PDF/이미지의 OCR·Vision 기반 기호 탐지 후보 및 사용자 확인**, PDF 도면의 도면명/회로·범례 정보 구조화 실험. A02가 별도 정확도·비용 검증 후 착수한다.

### P2 및 현재 범위 외

상용 DWG 서버 변환, 최종 공사비/표준품셈 계산, 모든 도면 기호·회로의 완전자동 정답 판정, 건축/기계/토목 전 공종 적산, RAG 시방서/KEC 자동 적합판정, 3D BIM, 로그인/팀 협업/클라우드 실사용, AR 배선 투시, 실제 계측 및 작업 자동 수행.

**중요:** 설계도상의 선은 실제 물리적 전선·전선관 경로가 아닐 수 있다. P0에서 선 길이를 케이블 포설 길이로 자동 확정하지 않는다.

## 6. 다중 형식 2D 도면 파싱 및 적산 데이터 원칙

- 입력별 파서는 분리하되, 사용자 주석·기호 품목·검수 및 내보내기는 **공통 모델**을 사용한다.
- DXF: 엔티티·블록 기반 구조 데이터가 존재할 경우 활용한다.
- 벡터 PDF: 텍스트·선·도형 위치를 추출할 수 있으나 CAD 블록 ID나 전기적 연결 정보가 유지된다고 가정하지 않는다.
- 스캔 PDF/PNG/JPG: 픽셀 이미지로 취급한다. P0는 사용자에 의한 위치 지정·카운트이며 자동 전기 기호 인식이라고 명시하지 않는다.
- PDF 페이지별 좌표·이미지 픽셀·CAD 월드 좌표를 구분하고, 정규화 좌표계와 변환값을 유지한다. PDF/이미지의 위치 근거는 원본 페이지와 영역 좌표로 기록한다.
- PDF/사진 내 선의 픽셀 길이는 실제 물리 길이가 아니다. 축척·치수 확인 없이는 m 단위 자동 물량을 생성하지 않는다.
- PDF 도면 렌더링에 PDF.js(Apache-2.0), 텍스트/기본 벡터 추출에 pdfplumber(BSD)를 후보로 검토한다. PyMuPDF는 AGPL/상용 이중 라이선스이므로 채택 전 적합성 검토가 필요하다. 최종 스택 선정은 A02의 ADR 소관이다.


- 블록 이름만으로 실제 품목·규격을 확정하지 않는다. A05 규칙과 프로젝트 범례 검토가 필요하다.
- CAD 엔티티 수는 설치 품목 수량과 다를 수 있다. 중첩 블록·배열·외부참조·익명/동적 블록·단위·축척·레이어 예외를 처리하거나 **지원하지 않는다는 경고**를 제공한다.
- 객체 근거는 파일 고유 ID, 객체 핸들, 중첩 참조 경로, 삽입 위치 등으로 재현 가능한 ID를 생성한다. DXF 재업로드 시 ID 지속성을 보장하지 못하는 경우 문서화한다.
- 원본 DXF는 변경하지 않는다. 매핑, 검수, 수동 추가, 제외 사유는 별도 저장한다.
- 계산은 가능한 한 결정론적 알고리즘으로 처리한다. AI가 수량·규격을 임의 생성하지 않는다.

| review_reason | 검수·제외·수동 추가 사유 |
| file_type / page_index | 원본 형식과 PDF 페이지 번호(0 또는 1 기반 인덱스 정책 명시) |
| coordinate_space / bounding_box | CAD 월드/PDF 페이지/이미지 픽셀 등 좌표계 및 선택 위치·영역 |
| extraction_method | CAD_PARSER / PDF_TEXT / PDF_VECTOR / MANUAL_MARKER 등 실제 획득 방식 |

CSV: 요약과 근거를 별도 파일. XLSX: Summary와 Evidence 두 개 시트. 내보내기에는 도면 ID·REV·시각 메타데이터를 포함. 출력 수량은 저장된 검수 결과와 동일해야 한다. 이 자료는 **기구 물량산출표**이지 최종 공사비 견적서가 아니다.

## 8. 최소 데이터 모델 (제안)

- `Project`: id, name, created_at
- `Drawing`: id, project_id, filename, file_hash, file_type, revision, units, parse_status, page_count
- `SourceObject`: id, drawing_id, file_type, page_index, coordinate_space, extraction_method, raw_handle(optional), insert_path(optional), entity_type, block(optional), layer(optional), normalized_geometry, warnings
- `ItemMapping`: id, drawing_id, match_criteria, item_code, status
- `TakeoffItem`: code, name, specification, unit
- `EvidenceReview`: source_object_id, inclusion_status, mapped_item_code, review_status, reason, updated_at
- `ManualObject`: id, drawing_id, page_index, coordinate_space, x, y, bounding_box(optional), item_code, note
- `ExportRecord`: id, drawing_id, snapshot_hash, format, created_at
- `Warning`: id, drawing_id, kind, severity, affected_objects

정확한 DB·API 계약은 A02가 ADR과 기술 문서로 결정한다. 로컬 지속성을 확보하되 초기부터 복잡한 SaaS 멀티테넌시를 구축하지 않는다.

## 9. 인수 기준 (Acceptance Criteria)

- **AC-01:** 정상 DXF/PDF/PNG/JPG 업로드로 해당 2D 도면 또는 PDF 페이지가 보이고 손상·비지원 파일은 오류를 안내한다.
- **AC-02:** 사용자가 미매핑 블록을 조명 등에 연결하면 지정된 범위의 객체만 집계한다.
- **AC-03:** 요약표 품목을 클릭하면 근거 객체가 도면에서 강조되고 역방향 선택도 가능하다.
- **AC-04:** 포함/제외/복원/품목 수정이 즉시 수량과 저장 결과에 반영된다.
- **AC-05:** 누락 기구를 수동 추가하면 위치·작성 사유·MANUAL_ADDED 기록이 남는다.
- **AC-06:** 미매핑·XREF 누락·특수 객체는 완전한 자동산출 결과로 가장하지 않는다.
- **AC-07:** 재열기 이후 매핑·검수·수동 추가가 복원된다.
- **AC-08:** CSV/XLSX 수량 및 근거 목록이 UI와 일치하며 한글 인코딩 문제도 없다.
- **AC-09:** 이동·회전·축척된 지원 블록의 좌표·선택 영역이 렌더링과 일치한다.
- **AC-10:** 지원되는 형식별 샘플 fixture의 기대 수량/위치와 정확히 일치하고 자동 회귀 테스트가 통과한다.
- **AC-11:** 벡터 PDF 샘플의 추출 가능한 문자와 위치를 조회/강조할 수 있다. 스캔 PDF는 텍스트 추출 불가 또는 OCR 미지원 상태를 정확히 안내한다.
- **AC-12:** PDF/이미지 위에 사용자가 기호 마커를 추가·삭제·재분류하면 산출표에 즉시 반영되고 저장·재열기 후에도 위치가 유지된다.
- **AC-13:** PDF 다중 페이지의 서로 다른 마커는 페이지 번호로 구분하고 줌/팬 후에도 올바른 위치를 유지한다.
- **AC-14:** P0 PDF/이미지 분석 화면에는 기호 자동 인식/회로 자동 해독 또는 실제 시공 길이 자동 산출을 완료한 것으로 표시하지 않는다.

지원하지 않는 중첩·동적 블록·외부참조는 조용히 잘못 집계하는 대신 경고와 미지원 상태로 분리하면 된다. 자동 테스트 통과를 실제 모든 현장 도면에 대한 정확도 보장으로 홍보하지 않는다.

## 10. 비기능 요구사항

- 기본 보안: 업로드 확장자/크기 검사, 예외 처리, 경로 조작 방지, 파서 자원 제한, 비밀키 커밋 금지.
- 추적성: 모든 확정 산출 결과는 원본 객체 또는 명시된 수동 입력을 근거로 가져야 한다.
- 데이터 지속성: 새로고침/재시작 후 복원.
- 접근성: 식별 가능한 선택 상태, 키보드 기본 조작, 에러 복구. A03 세부 기준 반영.
- 환경: 로컬 우선, 외부 유료 API 기본 미사용.
- 성능: A02-T002가 기준 시험환경, 파일 크기, 엔티티 수, 측정값을 보고한 후 정량 목표 채택.

## 11. 데이터·정답셋과 소유권

- 우선 A02가 생성 스크립트로 재현 가능한 합성 DXF/PDF/이미지 세트를 제작한다. A05가 기호-품목 의미 검토, A04가 기대값과 회귀 테스트 검증.
- 정상 블록, 중첩/회전/축척, 제외, 미매핑, 단위 미설정, XREF/손상 파일, 수동 추가뿐 아니라 벡터 PDF/스캔 PDF/다중 페이지/회전 PDF/PNG/JPG/왜곡된 이미지 입력별 **기대 결과와 경고 기대 결과**를 적는다.
- 공개 외부 도면은 '다운로드 가능'과 '학습/배포/상업적 재사용 가능'을 구분하고 사용 허가/라이선스를 확인한다.
- 고객의 실제 도면, 기밀 견적, 민감 시설 도면은 최초 MVP에서 사용하지 않는다.

### A02-T001 시작 범위

- `feat/a02-t001-bootstrap`에서 프로젝트 초기화, 설치/실행 가능한 최소 프론트·백엔드, README, 문서 템플릿, ADR-001, lint/type-check/test CI.
- 비승인 유료 서비스, 클라우드 제품 배포, DWG 서버 변환, AI API 호출, 최종 적산 계산 기능 구현 금지.
- ADR은 기술 선택·대안·비용·제약을 적는다. 완료 시 PR과 실제 실행 테스트를 보고한다.

### A02-T002B 시작 범위

- PDF.js 기반 PDF 표시와 pdfplumber 등 벡터 PDF 추출 가능성, PNG/JPG 뷰어 및 마커 좌표를 탐색한다.
- 스캔 여부 판별은 완벽한 자동 분류로 단정하지 않는다. 추출 가능한 PDF 문자/벡터 정보의 유무를 진단하고 사용자에게 '부분 지원/이미지형' 정보를 표시한다.
- PDF/이미지의 page_index, 좌표계, 마커 위치를 공통 산출 Evidence 구조로 통합할 수 있는지 실험한다.
- 무료/상용 라이선스, 성능, 실패 사례를 ADR에 기록한다. Vision API/OCR 유료 서비스 연결은 금지한다.

### A02-T002 시작 범위

- ezdxf로 INSERT/LINE/LWPOLYLINE/레이어/블록/단위/XREF 등 지원 가능성과 한계를 조사한다.
- 추적 가능한 객체 ID를 포함한 정규화 JSON 계약 초안을 제안한다.
- 소규모 합성 fixture 및 예상 결과를 생성하여 파싱 결과와 대조한다.
- 불확실한 블록·XREF는 확정 집계하지 않고 경고한다.
